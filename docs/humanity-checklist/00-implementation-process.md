# 00. 응우 사람다움 보강 실행 프로세스

## 목적

응우 사람다움 보강 작업을 진행할 때 수정 누락, 덮어쓰기, 단계 간 충돌을 줄이기 위한 실행 절차를 정의한다.

이 문서는 "어떤 순서로 확인하고, 수정하고, 기록하고, 다음 단계로 넘길지"에 집중한다.

## 기본 원칙

1. 한 번에 전 계층을 건드리지 않는다.
2. 항상 `기존 수정 대상 확인 -> 미비사항 검토 -> 현재 단계 수정 -> 문서 업데이트 -> 다음 단계 이월` 순서를 지킨다.
3. 상태 파일을 먼저, 응답 엔진을 그다음, 패턴/학습 계층을 마지막에 수정한다.
4. 생성 스크립트가 덮어쓸 수 있는 파일은 원본 스크립트와 결과 파일을 같이 본다.
5. 각 단계가 끝날 때마다 "이번 단계에서 끝난 것 / 다음 단계로 넘길 것"을 문서에 남긴다.

## 공통 반복 프로세스

모든 단계는 아래 순서를 반복한다.

### 1. 기존 수정 대상 확인

- 이번 단계 대상 파일이 무엇인지 확인
- 이미 수정된 내용이 있는지 확인
- 현재 상태가 기존 문서와 어긋나는지 확인

### 2. 미비사항 검토

- 원래 목표 대비 부족한 점을 다시 점검
- 이전 단계 수정이 현재 단계에 새 요구사항을 만들었는지 확인
- 필요하면 이번 단계 대상 리스트에 항목 추가

### 3. 현재 단계 수정 진행

- 이번 단계 책임 범위 안에서만 수정
- 다른 단계 책임 파일은 원칙적으로 건드리지 않음
- 예외적으로 건드린 경우 반드시 이월 메모에 남김

### 4. 수정 내용 대응 확인

- 파일 구조가 깨지지 않았는지 확인
- 연관 상태/스크립트/런타임 참조가 끊기지 않았는지 확인
- 다음 단계에서 덮어쓸 위험이 있는지 확인

### 5. 문서 업데이트

- 이번 단계 문서에
  - 무엇을 수정했는지
  - 무엇이 아직 남았는지
  - 어떤 위험이 남았는지
  를 반영

### 6. 다음 단계 이월 작성

- 다음 단계로 넘길 항목이 있으면 명시적으로 기록
- "나중에 보면 됨" 식으로 남기지 말고 파일/항목 단위로 적기

## 단계 순서

### 1단계. 상태/기억/감각 계층 정리

- 목표:
  - 사람다움 보강에 필요한 현재 상태, 감정 여운, 생활 리듬, 미세 디테일을 먼저 안정화
- 이유:
  - 가장 충돌 위험이 낮고, 이후 응답 엔진이 참고할 기반이 됨

### 2단계. 응답 엔진/Proactive 조정

- 목표:
  - 실제 응답과 proactive 흐름에 1단계 상태 구조가 반영되게 만들기
- 이유:
  - 사용자 체감에 가장 직접적인 계층

### 3단계. 패턴 카탈로그/승인 패턴 정리

- 목표:
  - 반복되는 응답 구조와 승인 패턴을 현재 기준에 맞게 정리
- 이유:
  - worker 수정만으로 남는 패턴 오염을 줄이기 위함

### 4단계. 학습 루프/생성 스크립트 정리

- 목표:
  - 이후 자동 생성/재학습 시 다시 옛 패턴이 들어오지 않게 원본 계층 정리
- 이유:
  - 가장 덮어쓰기 위험이 크므로 마지막 단계에 진행

## 단계 종료 기준

각 단계는 아래 항목을 만족해야 종료로 본다.

1. 대상 파일 수정 완료
2. 이번 단계 문서 업데이트 완료
3. 다음 단계 이월 항목 기록 완료
4. 현재 단계 변경이 다음 단계에서 덮어써질 위험 여부 확인 완료

## 기록 규칙

- `완료`: 이번 단계에서 수정 끝
- `부분 완료`: 일부 반영, 후속 필요
- `이월`: 다음 단계에서 처리
- `보류`: 지금 건드리면 위험해서 남김
